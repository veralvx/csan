# csan

Cutter call numbers for library cataloging, as a Rust library and a Typst
plugin.

`csan` derives shelf-ready cutter numbers from author names (or, for
anonymous works, titles) using two methods:

- **Cutter-Sanborn three-figure** — a lookup against the bundled
  Cutter-Sanborn table (12,000+ entries), with an optional call number
  prefix and a lowercase work mark derived from the title.
- **Library of Congress** — the LoC character-branching rules
  ([Cutter table](https://www.loc.gov/aba/pcc/053/table.html),
  [CSM G 63](https://www.loc.gov/aba/publications/FreeCSM/G063.pdf)),
  producing an initial plus a digit sequence.

Input names are normalized first: whitespace and punctuation are stripped,
diacritics and ligatures are folded to ASCII (`Čapek` → `Capek`, `Strauß` →
`Strauss`), `Mc`/`M'` prefixes expand to `Mac`, and `St`/`Ste` expand to
`Saint`/`Sainte`, matching the conventions of the underlying tables.

## Rust usage

Add the library with `cargo add csan-core`. (Up to 0.5.x the library was
published as `csan`; that name now belongs to the command-line tool.)

```rust
use csan_core::{
    Attribution, Author, CutterConfig, CutterGenerator, CutterLocMethod,
    CutterSanbornMethod, Opus,
};

let entry = Attribution::Both {
    author: Author::new("Charles", "Dickens"),
    opus: Opus::new("Oliver Twist"),
};

let sanborn = CutterSanbornMethod::generate(&entry, CutterConfig::default())?;
assert_eq!(sanborn.to_string(), "D548o");

let loc = CutterLocMethod::generate(&entry, CutterConfig::default())?;
assert_eq!(loc.to_string(), "D535");
# Ok::<(), csan_core::NormalizationError>(())
```

`CutterConfig` tunes the output: `prefix_len` and `suffix_len` control the
Cutter-Sanborn prefix and work mark, and `max_len` controls the LoC digit
count (clamped to 4). Works without an author use
`Attribution::OpusOnly(...)` and are cuttered by title, including the LoC
numeral rule (`"100 best recipes"` → `A153`).

## Command line

The `csan` crate (`crates/csan`) provides the `csan` binary. Install it
with `cargo install csan`, the shell/PowerShell installers or archives
attached to each
[GitHub release](https://github.com/veralvx/csan/releases), or the Python
package below:

```sh
$ csan --forename Charles --surname Dickens --title "Oliver Twist"
D548o
$ csan --method cutter-loc --forename Charles --surname Dickens
D535
```

`--method` selects the method, `cutter-sanborn` (the default) or
`cutter-loc`, and at least one non-blank input (`--forename`, `--surname`,
`--title`) is required.
`--prefix-len`/`--suffix-len` tune the Cutter-Sanborn output, `--max-len`
the LoC digits, and `--json` emits the parts as a JSON object. Errors exit
non-zero with a message on stderr.

## Python

`crates/csan-py` packages the library for Python (CPython 3.9+, abi3
wheels) under the PyPI name `csan`, including the CLI as a console
script:

```sh
pip install csan        # library + CLI
uv tool install csan    # just the CLI, isolated
```

```python
import csan
csan.cutter_sanborn(surname="Dickens", title="Oliver Twist")  # 'D548o'
csan.cutter_loc_detailed(surname="Carter")
# {'alpha_prefix': 'C', 'numeric': 378, 'formatted': 'C378'}
```

See [`crates/csan-py/README.md`](crates/csan-py/README.md) for the
full API and the maturin build/publish flow.

## JavaScript (npm)

`crates/csan-web` exposes the library to JavaScript via WebAssembly,
packaged with `wasm-pack` and published to npm as
[`@veralvx/csan`](https://www.npmjs.com/package/@veralvx/csan) (a Node
package):

```sh
npm install @veralvx/csan
```

```js
const { cutterLoc, cutterSanborn } = require("@veralvx/csan");
cutterSanborn({ surname: "Dickens", title: "Oliver Twist" }); // "D548o"
cutterLoc({ surname: "Carter" }); // "C378"
```

See [`crates/csan-web/README.md`](crates/csan-web/README.md) for
build, examples (Node and browser), and npm publishing instructions.

## Typst usage

The Typst package lives in `crates/csan-typst/pkg` and exposes two
functions:

```typ
// Replace <version> with the installed release.
#import "@local/csan:<version>": cutter-sanborn, cutter-loc

#cutter-sanborn(
  forename: "Charles",
  surname: "Dickens",
  title: "Oliver Twist",
) // -> "D548o"

#cutter-loc(surname: "Carter") // -> "C378"
```

Both accept `forename`, `surname`, and `title` (at least one of
author/title must be non-blank; blank strings count as absent).
`cutter-sanborn` also takes `prefix-len` and `suffix-len`; `cutter-loc`
takes `max-len`. Pass `detailed: true` to receive a dictionary of the parts
(`alpha_prefix`, `numeric`, …) instead of the formatted string. Requires
Typst 0.14.2 or later.

Until the package is published to Typst Universe, install it as a
[local package](https://github.com/typst/packages#local-packages): extract
the `csan_typst-<version>.tar.gz` attached to each GitHub release into
`{data-dir}/typst/packages/local/csan/<version>/` (or copy
`crates/csan-typst/pkg` there), then import `@local/csan:<version>`. The
plugin binary alone is attached as `csan_typst.wasm`.

### Building the plugin

The compiled plugin (`csan_typst.wasm`) is committed alongside the
package, so Typst users don't need a Rust toolchain. To rebuild it after
changing the Rust code:

```sh
rustup target add wasm32-unknown-unknown
just wasm        # build + install into crates/csan-typst/pkg
just wasm-opt    # optional: shrink with binaryen's wasm-opt
just typst-test  # compile the assert-based plugin test suite
```

## Releasing

`just release <major|minor|patch>` (on an up-to-date, clean `main`) bumps
the workspace version, the `csan-core` dependency pin, and the Typst
package version, prepends the release's section to `CHANGELOG.md` with
git-cliff, then commits, tags, and pushes. It refuses a bump smaller than
the unreleased breaking changes require. The tag starts the Release workflow, which uses
[dist](https://opensource.axo.dev/cargo-dist/) to build the `csan` binaries
and installers and attaches, to the same GitHub release:

- the Typst plugin (`csan_typst.wasm`) and package
  (`csan_typst-<version>.tar.gz`);
- the Python wheels (abi3, Linux/musllinux/macOS/Windows on x86_64 and
  aarch64) and sdist;
- the Node npm package (`veralvx-csan-<version>.tgz`).

Three workflows then publish the release, each only once the Release
workflow has succeeded and each with trusted publishing (the one-time setup
is described at the top of each file):

- `publish-pypi.yml` uploads the release's wheels and sdist to
  [PyPI](https://pypi.org/project/csan/) (it runs when the Release
  workflow completes);
- `publish-npm.yml` publishes the release's npm tarball as
  [`@veralvx/csan`](https://www.npmjs.com/package/@veralvx/csan);
- `publish-crates.yml` publishes `csan-core`, then `csan`, from the tag to
  [crates.io](https://crates.io/crates/csan).

The npm and crates.io workflows start on the tag push and wait for that
tag's Release run, since crates.io trusted publishing does not accept
`workflow_run` events. Each workflow can also be run by hand for a release
tag, and skips whatever that release already published.

## Development

The repository pins Rust 1.97 (`rust-toolchain.toml`). `just checks` runs
the core CI gates: `cargo check`/`test`/`clippy -D warnings` (all
targets, with the `cargo`, `pedantic`, and `restriction` clippy groups
enabled), `cargo fmt --check`, `cargo doc -D warnings`, `cargo audit`,
`dprint check`, and `cog check` for Conventional Commits. CI additionally builds and smoke-tests the
Typst plugin, the Python wheel, and the npm package. Lint policy —
including the reason for every allowed lint — lives in the workspace
`Cargo.toml` and `clippy.toml`.
