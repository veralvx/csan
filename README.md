# csan

Cutter call numbers for library cataloging, as a Rust library and a Typst
plugin.

`csan` derives shelf-ready cutter numbers from author names (or, for
anonymous works, titles) using two methods:

- **Cutter-Sanborn three-figure** — a lookup against the bundled
  Cutter-Sanborn table (12,000+ entries), with an optional call number
  prefix and a lowercase work mark derived from the title.
- **Library of Congress** — the LoC character-branching rules
  ([Cutter table](https://www.loc.gov/aba/pcc/053/table.html),
  [CSM G 63](https://www.loc.gov/aba/publications/FreeCSM/G063.pdf)),
  producing an initial plus a digit sequence.

Input names are normalized first: whitespace and punctuation are stripped,
diacritics and ligatures are folded to ASCII (`Čapek` → `Capek`, `Strauß` →
`Strauss`), `Mc`/`M'` prefixes expand to `Mac`, and `St`/`Ste` expand to
`Saint`/`Sainte`, matching the conventions of the underlying tables.

## Rust usage

```rust
use csan::{
    Attribution, Author, CutterConfig, CutterGenerator, CutterLocMethod,
    CutterSanbornMethod, Opus,
};

let entry = Attribution::Both {
    author: Author::new("Charles", "Dickens"),
    opus: Opus::new("Oliver Twist"),
};

let sanborn = CutterSanbornMethod::generate(&entry, CutterConfig::default())?;
assert_eq!(sanborn.to_string(), "D548o");

let loc = CutterLocMethod::generate(&entry, CutterConfig::default())?;
assert_eq!(loc.to_string(), "D535");
# Ok::<(), csan::NormalizationError>(())
```

`CutterConfig` tunes the output: `prefix_len` and `suffix_len` control the
Cutter-Sanborn prefix and work mark, and `max_len` controls the LoC digit
count (clamped to 4). Works without an author use
`Attribution::OpusOnly(...)` and are cuttered by title, including the LoC
numeral rule (`"100 best recipes"` → `A153`).

## Command line

`crates/csan-cli` provides the `csan` binary (`cargo install --path
crates/csan-cli`, or via the Python package below):

```sh
$ csan --cutter-sanborn --cutter-loc \
    --given-name Charles --family-name Dickens --title "Oliver Twist"
D548o
D535
```

Select at least one method (`--cutter-sanborn`, `--cutter-loc`) and provide
at least one non-blank input (`--given-name`, `--family-name`, `--title`).
`--prefix-len`/`--suffix-len` tune the Cutter-Sanborn output, `--max-len`
the LoC digits, and `--json` emits the parts as a JSON object. Errors exit
non-zero with a message on stderr.

## Python

`crates/csan-py` packages the library for Python (CPython 3.9+, abi3
wheels) under the PyPI name `csan`, including the CLI as a console
script:

```sh
pip install csan        # library + CLI
uv tool install csan    # just the CLI, isolated
```

```python
import csan
csan.cutter_sanborn(family_name="Dickens", title="Oliver Twist")  # 'D548o'
csan.cutter_loc_detailed(family_name="Carter")
# {'alpha_prefix': 'C', 'numeric': 378, 'formatted': 'C378'}
```

See [`crates/csan-py/README.md`](crates/csan-py/README.md) for the
full API and the maturin build/publish flow.

## JavaScript (npm)

`crates/csan-web` exposes the library to JavaScript via WebAssembly,
packaged for npm with `wasm-pack`:

```js
import { cutterLoc, cutterSanborn } from "csan-web";
cutterSanborn({ familyName: "Dickens", title: "Oliver Twist" }); // "D548o"
cutterLoc({ familyName: "Carter" }); // "C378"
```

See [`crates/csan-web/README.md`](crates/csan-web/README.md) for
build, examples (Node and browser), and npm publishing instructions.

## Typst usage

The Typst package lives in `crates/csan-typst/pkg` and exposes two
functions:

```typ
#import "@preview/csan:0.1.0": cutter-sanborn, cutter-loc

#cutter-sanborn(
  given-name: "Charles",
  family-name: "Dickens",
  title: "Oliver Twist",
) // -> "D548o"

#cutter-loc(family-name: "Carter") // -> "C378"
```

Both accept `given-name`, `family-name`, and `title` (at least one of
author/title must be non-blank; blank strings count as absent).
`cutter-sanborn` also takes `prefix-len` and `suffix-len`; `cutter-loc`
takes `max-len`. Pass `detailed: true` to receive a dictionary of the parts
(`alpha_prefix`, `numeric`, …) instead of the formatted string. Requires
Typst 0.14.2 or later.

Until the package is published to Typst Universe, use it locally by copying
`crates/csan-typst/pkg` into your [local package directory](https://github.com/typst/packages#local-packages) as
`csan/0.1.0`, or import `lib.typ` by relative path.

### Building the plugin

The compiled plugin (`csan.wasm`) is committed alongside the
package, so Typst users don't need a Rust toolchain. To rebuild it after
changing the Rust code:

```sh
rustup target add wasm32-unknown-unknown
just wasm        # build + install into crates/csan-typst/pkg
just wasm-opt    # optional: shrink with binaryen's wasm-opt
just typst-test  # compile the assert-based plugin test suite
```

## Development

The repository pins Rust 1.97 (`rust-toolchain.toml`). `just checks` runs
the core CI gates: `cargo check`/`test`/`clippy -D warnings` (all
targets, with the `cargo`, `pedantic`, and `restriction` clippy groups
enabled), `cargo fmt --check`, `cargo doc -D warnings`, `cargo audit`,
`dprint check`, and `cog check` for Conventional Commits. CI additionally builds and smoke-tests the
Typst plugin, the Python wheel, and the npm package. Lint policy —
including the reason for every allowed lint — lives in the workspace
`Cargo.toml` and `clippy.toml`.
